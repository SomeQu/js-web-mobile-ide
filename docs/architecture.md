# Мобильная IDE для JS/TS — Архитектура (v0.1, черновик)

## 1. Принципы, зафиксированные в обсуждении

- Платформа старта: **iOS** (жёсткие ограничения → если решение работает там, на Android оно точно заработает, а не наоборот).
- Целевой функционал — **единый для всех пользователей**, без урезанной "учебной" версии: должен открывать реальные проекты (принесённые из интернет-кафе, с флешки, из git), а не только генерировать код с нуля.
- Основной путь исполнения — **on-device (локально)**, чтобы приложение оставалось бесплатным без обязательных серверных расходов на пользователя. Облако — опциональный резервный слой, не обязательный.
- Совместимость обеспечивается через **package.json + lock-файл**, а не через копирование чужого `node_modules` (он всё равно бинарно несовместим с iOS).
- Реклама — под вопросом как модель монетизации, приоритет — не ломать UX работы с кодом.

## 2. Слои системы

```
┌─────────────────────────────────────────────┐
│  UI слой (SwiftUI)                           │
│  Редактор, файловый менеджер, терминал-вид   │
└───────────────┬───────────────────────────────┘
                │
┌───────────────▼───────────────────────────────┐
│  Мост / оркестратор (Swift ↔ JS)              │
│  Передача файлов, команд, событий             │
└───────────────┬───────────────────────────────┘
                │
┌───────────────▼───────────────────────────────┐
│  Исполнительное ядро (WKWebView / JSCore)     │
│  - Резолвер зависимостей                      │
│  - Виртуальная ФС                             │
│  - esbuild-wasm / swc-wasm (сборка)           │
│  - Полифиллы Node API                         │
│  - Live preview (Service Worker / evaluateJS) │
└───────────────┬───────────────────────────────┘
                │
┌───────────────▼───────────────────────────────┐
│  Внешние сервисы (через обычные HTTPS-запросы)│
│  npm registry, git remote, Anthropic API      │
└─────────────────────────────────────────────────┘
```

## 3. Компоненты и их назначение

### 3.1 UI слой (нативный, Swift/SwiftUI)
- Редактор кода: скорее всего Monaco (веб-компонент внутри WKWebView) или CodeMirror — вопрос производительности на мобильном рендере, нужно тестировать оба.
- Файловый менеджер поверх виртуальной ФС.
- Терминал-вид (эмуляция вывода команд вашего JS-рантайма, не настоящий shell).
- AI-ассистент как боковая панель — чат + diff-view для правок.

### 3.2 Мост (Swift ↔ JavaScriptCore/WKWebView)
- Передача файлового дерева, событий сохранения, команд запуска.
- `evaluateJavaScript()` для инъекции изменений в live preview.
- Обработка сообщений от Service Worker (перехваченные fetch-запросы).

### 3.3 Исполнительное ядро — самая тяжёлая часть проекта

| Подсистема | Задача | Технология |
|---|---|---|
| Резолвер зависимостей | semver, дедупликация, hoisting | свой JS-модуль, референс — резолверы pnpm/Yarn Berry |
| Клиент npm registry | скачивание `.tgz`, метаданные | HTTP-клиент на fetch |
| Распаковка пакетов | gzip/tar в JS | готовые чистые JS-библиотеки |
| Виртуальная ФС | эмуляция POSIX-путей без реальных симлинков | свой слой поверх iOS Documents-директории |
| Бандлер/транспилятор | JSX/TS → JS | esbuild-wasm или swc-wasm |
| Node API полифиллы | fs/path/process/buffer заглушки | node-stdlib-browser и аналоги |
| Live preview | рендер результата | WKWebView + Service Worker (перехват fetch) |
| HMR (упрощённый) | обновление без сети | прямой JS-инжект после пересборки, без настоящего WS-сервера Vite |

### 3.4 AI-ассистент (расширение IDE)
- Чат поверх Anthropic Messages API (обычный HTTPS, никаких ограничений iOS).
- Свой набор tool-функций: `read_file`, `write_file`, `apply_diff`, `search_codebase`, `get_open_file`, опционально `run_command` (через ваш JS-рантайм, не настоящий bash).
- Контекст проекта передаётся в system-промпт: структура файлов, открытый файл, курсор/выделение.

### 3.5 Git
- Собственный git-клиент (изоморфный git на JS, аналог isomorphic-git) поверх виртуальной ФС — реальный `git` бинарник на iOS не запустить.

## 4. Что архитектурно закрыто, что открыто

**Закрыто (решение принято по ходу обсуждения):**
- Исполнение JS/TS — JavaScriptCore/WKWebView, не настоящий Node.
- npm — свой резолвер + скачивание пакетов, не копирование чужого node_modules.
- Сеть — только исходящие fetch/WebSocket-клиент, без сервера на устройстве.
- AI-ассистент — tool-use поверх Messages API, без нативного бинарника Claude Code.

**Открыто (требует решения дальше):**
- Monaco vs CodeMirror — тест производительности на реальных устройствах.
- Формат виртуальной ФС — насколько точно эмулировать node_modules-подобную структуру vs PnP-формат.
- Реестр WASM-совместимых замен для популярных нативных пакетов (sharp, sqlite3 и т.д.) — что войдёт в MVP.
- Модель монетизации (реклама / freemium / подписка) — как соотносится с "бесплатно и без ограничений".
- Нужен ли облачный fallback-контейнер для пакетов, которые в принципе не работают локально, и когда его подключать.

## 5. Возможный порядок реализации MVP

1. Виртуальная ФС + редактор (Monaco/CodeMirror) — просто открыть/редактировать файлы, без исполнения.
2. Live preview для чистого HTML/CSS/JS через WKWebView (без npm вообще) — самый быстрый способ показать "оно работает".
3. esbuild-wasm интеграция — транспиляция JSX/TS.
4. Резолвер + скачивание npm-пакетов (начать с топ-20 фронтенд библиотек: React, Vue, lodash и т.д., без экзотики).
5. Node API полифиллы — по мере того, какие пакеты реально ломаются без них.
6. AI-ассистент как отдельный, почти независимый модуль (можно параллелить с 1-5).
7. Git-клиент.
